# 影像前處理對商品條碼、電子發票 QR 與營養標示辨識效能之影響研究（實驗設計 修訂版）

> 本文件為模組一的實驗設計，範圍依 `docs/adr/0004-preprocess-scope-static-photos.md`。
> 與初版的差異見文末「附錄 B 修訂紀錄」；與現有程式的對照見「附錄 A」。

## 一、研究目的

本實驗探討影像前處理能否提升**靜態照片**中商品條碼、電子發票 QR 與營養標示的辨識效能，
並比較不同前處理方法在各種影像劣化條件下的改善程度與副作用。

研究不訓練、不微調任何神經網路（專案規則 5），而是在影像進入現成辨識引擎前，
以傳統影像處理改善影像品質，降低模糊、雜訊、低解析度、光線不均、反光、旋轉及透視變形造成的辨識困難。
進一步研究**規則式**自適應前處理：先量測影像品質，再依量測值選擇處理方式，並與固定流程比較。

### 1.1 研究範圍

| 項目 | 範圍 |
| --- | --- |
| 使用情境 | 無法重拍的靜態照片：相簿匯入、截圖、冷啟動上傳。**不含** APP 相機的即時掃描（即時掃描使用手機端現成套件，使用者會自行調整角度，見 ADR 0004） |
| 商品條碼 | 台灣零售商品條碼：EAN-13 為主，含 EAN-8、UPC-A |
| 電子發票 QR | 電子發票證明聯上的左、右兩個 QR Code |
| 營養標示 | 食品包裝上的營養標示表（含曲面、亮面反光、繁體中文、小字） |

結論只適用於上述情境，不外推到即時掃描或一般文件 OCR。

### 1.2 核心研究問題

1. 不同前處理方法能否提升三種任務的辨識效能？
2. 哪些前處理方法對特定劣化條件最有效？
3. 多種方法組合（疊加或依序嘗試）是否一定比單一方法有效？
4. 前處理是否會造成**誤讀**（回傳內容但內容錯誤），或讓原本可辨識的影像變得無法辨識？
5. 依影像品質量測值選擇處理方式的自適應方法，能否在辨識品質與運算時間之間取得較好的平衡？
6. 前處理帶來的改善，與單純更換辨識引擎相比有多大？

### 1.3 研究假設（皆可由實驗數據檢驗）

- **H1**：在劣化影像上，最佳前處理策略的完全正確率高於 Baseline（同一引擎、不做前處理）。
- **H2**：不同劣化條件的最佳單一方法不同；不存在在所有劣化條件下都是最佳的單一方法。
- **H3**：至少有一組疊加流程的完全正確率低於其所含的最佳單一方法（方法之間會互相干擾）。
- **H4**：自適應策略的完全正確率不低於最佳逐步升級策略（差距在預先設定的容許範圍內），且總處理時間較短。
- **H5**：前處理會使部分樣本由「正確」變成「誤讀」；誤讀率須與成功率一併報告。

## 二、實驗整體流程

0. **選定辨識引擎**（階段零，見 7.1）。
1. 蒐集三種任務的原始影像，建立正確答案（Ground Truth）。
2. 依原始樣本切分 dev／test（見 3.4）。
3. 建立 Baseline（選定引擎、不做前處理）。
4. 產生人工劣化變體。
5. 對每個變體執行所有單一方法，並記錄每一種方法的結果（不提早停止）。
6. 執行疊加流程。
7. 由單一方法的結果，離線計算各種逐步升級策略的結果。
8. 建立自適應策略（規則式，門檻只在 dev 調整）。
9. 比對結果與 Ground Truth，計算成功率、誤讀率、欄位正確率與處理時間。
10. 以原始樣本為單位進行統計分析。
11. 在 dev 上選定策略後，於 test 上執行一次，作為正式結論。

**核心控制原則：** 同一個變體會進入所有實驗組；除前處理方式外，辨識引擎、版本、參數與判定方式完全相同。

## 三、測試資料集設計

### 3.1 資料集規模

| 任務 | 原始樣本（初期） | Ground Truth |
| --- | --- | --- |
| 商品條碼 | 100～200 個**不同產品** | 條碼完整數字 |
| 電子發票 QR | 50～100 張**不同發票** | 左、右兩個 QR 的原始位元組 |
| 營養標示 | 100～200 個**不同產品** | 表格四角座標、各欄位數值與單位、全文 |
| 負樣本 | 每種任務 20 張以上 | 標記為「影像中沒有目標」，用來量測誤報 |

規模以「不同原始樣本」計算，不以變體數計算。資料不足時，應優先增加不同產品、包材、版面與拍攝條件，
而不是對少數照片大量產生變體：變體能增加劣化條件的覆蓋，卻不能增加內容的多樣性。

### 3.2 資料來源

**A. 真實影像**：手機實際拍攝，每張標記拍攝條件（距離、角度、光線、材質、是否曲面）。

**B. 人工劣化影像**：以品質良好的真實照片為原圖，依第四章產生參數已知的變體。保留原圖與其 Ground Truth，並記錄每個變體的劣化類型、程度與隨機種子。

真實影像反映實際使用情境；人工劣化影像可控制單一變因。**兩者分開統計與報告**，避免人工劣化的結果掩蓋真實情境的表現。
選定策略的最終依據是真實影像的 test 結果。

### 3.3 Ground Truth 與判定方式

| 任務 | Ground Truth | 判定 |
| --- | --- | --- |
| 商品條碼 | 完整數字字串 | 正確：與真值完全一致。誤讀：有回傳但不一致（含其他合法格式）。未讀到：沒有回傳 |
| 電子發票 QR | 左、右兩個 QR 的原始位元組 | 正確：兩個都讀到且位元組完全一致。部分：只讀到一個且一致。誤讀：任一回傳內容不一致。未讀到：兩個都沒有 |
| 營養標示 | 表格四角座標；欄位：每一份量、本包裝含份數、熱量、蛋白質、脂肪、飽和脂肪、反式脂肪、碳水化合物、糖、鈉（數值＋單位）；全文 | 見 8.2 |

營養標示的欄位真值以 CSV 或 JSON 保存，由兩人獨立標記後比對，不一致處由第三人裁定。
不要用 Excel 編輯含長數字的 manifest（長數字會被轉成科學記號、前導 0 會遺失）。

### 3.4 資料切分與避免資料洩漏

- 以**原始樣本**（同一產品／同一張發票）為單位切分為 **dev** 與 **test**。本研究不訓練模型，不設 train。
- 同一原始樣本的所有變體（模糊版、旋轉版、縮小版等）必須與原圖在同一分組。
- 方法選擇、參數、自適應規則與門檻**只能**依 dev 結果調整。
- test 只在策略全部定案後執行一次，作為正式結論；test 結果不得回頭用來調整任何規則、門檻或提示（專案規則 7）。
- 若定案後發現問題必須修改，修改後的結果須註明「已看過 test」，並另收一批新資料重新驗證。

## 四、影像劣化條件設計

| 劣化條件 | 模擬方式 | 建議層級（每種 4～5 級） |
| --- | --- | --- |
| 失焦模糊 | Gaussian Blur | σ 由輕至重 |
| 手震模糊 | Motion Blur（線性核，含方向） | 核長度由短至長 |
| 雜訊 | Gaussian Noise；Salt-and-Pepper Noise | 標準差／比例由低至高 |
| 低解析度 | 縮小倍率（例如 1.0、0.6、0.35、0.15、0.08） | 依條碼模組寬度換算 |
| 亮度不足 | 整體增益降低 | 由輕至重 |
| 對比不足 | 壓縮灰階動態範圍 | 由輕至重 |
| 光線不均 | 漸層亮度、陰影 | 由輕至重 |
| 反光／光斑 | 加入高亮橢圓區域 | 面積與位置 |
| 旋轉 | 平面旋轉 | 例如 0°、15°、30°、45°、80° |
| 透視變形 | Perspective Transform | 不同斜拍角度 |
| 曲面 | 圓柱面映射（瓶身、罐身） | 不同曲率 |
| JPEG 壓縮 | 重新壓縮 | 品質 90、70、50、30 |

### 4.1 劣化實驗原則

1. 單一劣化實驗每次只改變一項條件，用來分析該因素的影響。
2. 每個變體都有明確參數與隨機種子，不以「看起來比較模糊」分類。
3. 另設複合情境，例如「低亮度＋模糊」、「旋轉＋透視」、「反光＋曲面」，並與單一劣化分開報告。
4. **不排除劣化過重的樣本**，改以「劣化程度 → 成功率」的曲線呈現，標出前處理開始救不回來的程度。
   若事先排除，排除標準容易受到結果影響。
5. 人工劣化與真實影像分開報告。
6. 人工劣化只用來找方向與範圍；最終數值以真實照片確認。

## 五、前處理方法設計

### 5.1 共通方法

| 方法 | 主要目的 | 適用問題 | 可能副作用 |
| --- | --- | --- | --- |
| 灰階轉換 | 簡化影像 | 色彩干擾 | 失去色彩資訊；多數引擎內部已轉灰階，效果可能為零 |
| Gaussian Blur | 平滑高頻雜訊 | 細微雜訊 | 邊緣更模糊 |
| Median Filter | 去除椒鹽雜訊 | 黑白散點 | 核過大破壞細節 |
| CLAHE | 改善局部對比 | 低對比、光線不均 | 放大雜訊 |
| Otsu Threshold | 全域二值化 | 前景背景對比明顯 | 不適合光線不均 |
| Adaptive Threshold | 局部二值化 | 陰影、光線不均 | 參數不當破壞細線與小字 |
| Sharpening | 強化邊緣 | 輕微模糊 | 放大雜訊、邊緣假影；**可能造成條碼誤讀** |
| 放大／多尺度 | 調整輸入尺寸 | 小尺寸影像 | 放大無法還原遺失的資訊 |
| Deskew | 修正傾斜 | 旋轉 | 角度估計錯誤造成二次傾斜 |
| Perspective Correction | 修正斜拍 | 透視變形 | 角點偵測錯誤造成變形 |
| 光斑修補 | 修補反光區域 | 亮面包裝 | 可能抹除光斑下的文字 |

### 5.2 商品條碼

條碼依賴線條的寬度與間距，處理時須避免改變線寬。
測試：灰階、CLAHE、中值濾波、Otsu、Adaptive Threshold、銳化、多尺度、Deskew、條碼區域裁切（ROI）。

### 5.3 電子發票 QR

須保留定位圖案與資料模組的形狀。發票通常有兩個 QR 並排，處理方法不得讓兩者互相干擾或只保留其中一個。
測試：灰階、CLAHE、Otsu、Adaptive Threshold、去噪、Deskew、透視校正、ROI 裁切與適當放大。
特別觀察二值化、去噪與銳化是否改變模組形狀或連接關係。

### 5.4 營養標示

營養標示須先定位表格，再交給 OCR。定位與 OCR 分開評估，才能判斷失敗的原因。
測試：表格定位（輪廓、直線交點）、透視校正、光斑修補、CLAHE、去噪、Otsu／Adaptive Threshold、
形態學運算（分離表格線與文字）、表格區域裁切。
形態學運算須避免文字筆畫與表格線黏合，也不得刪除小數點等細小字元。

## 六、實驗組別設計

### 6.1 策略類型

| 策略 | 做法 | 說明 |
| --- | --- | --- |
| 單一方法 | 只做一種處理，送辨識一次 | 觀察各方法的獨立效果 |
| 固定流程（疊加） | 同一張影像依序做多種處理，送辨識一次 | 例：去噪 → 二值化 |
| 逐步升級（依序嘗試） | 各方法**分別**從原圖處理，依序送辨識，第一次有結果即停止 | 系統目前的條碼做法 |
| 自適應 | 先量測品質，再依規則選擇方法 | 見 6.6 |

### 6.2 基準組（Baseline）

| 組別 | 處理方式 |
| --- | --- |
| A0 | 原始影像直接送入選定引擎（引擎內建的影像處理維持預設，並記錄其設定） |

所有後續實驗都與 A0 比較。另列出階段零中其他引擎「不做前處理」的結果作為參考，
用來說明前處理的改善與更換引擎的改善孰大孰小。

### 6.3 單一方法

每次只使用一種方法。為了讓 6.5 的逐步升級可以離線計算，**每個變體都執行所有單一方法，不提早停止**，
並逐一記錄每種方法的結果（正確／誤讀／未讀到）與耗時。

以商品條碼為例：

| 編號 | 處理方式 |
| --- | --- |
| B-00 | 原始影像（即 A0） |
| B-01 | 灰階 |
| B-02 | Otsu 二值化 |
| B-03 | Adaptive Threshold |
| B-04 | CLAHE |
| B-05 | 中值濾波 |
| B-06 | 銳化 |
| B-07 | 多尺度（放大、縮小各一） |
| B-08 | Deskew |
| B-09 | ROI 裁切 |

電子發票 QR（Q-xx）與營養標示（L-xx）依其特性另列，不強迫三種任務使用相同方法。

### 6.4 固定流程（疊加）

疊加流程無法由單一方法的結果推算，必須實際執行。只選擇有影像處理依據的組合，不窮舉：

| 編號 | 處理流程 |
| --- | --- |
| C-01 | 去噪 → 二值化 |
| C-02 | CLAHE → 二值化 |
| C-03 | CLAHE → 去噪 |
| C-04 | 去噪 → CLAHE → 二值化 |
| C-05 | Deskew → 去噪 → 二值化 |
| C-06 | 透視校正 → CLAHE → 二值化 |
| C-07 | 光斑修補 → CLAHE（營養標示） |

### 6.5 逐步升級（依序嘗試）

因為各方法都從原圖獨立處理，任何「方法子集＋順序」的結果都能由 6.3 的紀錄直接算出：
依序找第一個有回傳內容的方法，再看它是否正確。疊加流程也可以當作其中一個步驟加入。

以**貪婪法**選擇步驟與順序：

1. 從 A0 開始。
2. 在尚未加入的方法中，選擇能救回最多「目前仍失敗的樣本」且不增加誤讀的方法，加到最後。
3. 重複步驟 2，直到新增一步救回的樣本少於預先設定的下限，或總耗時超過上限。

貪婪法的每一步就是該方法的邊際貢獻，也直接得到建議的順序。選擇只在 dev 上進行。

### 6.6 消融實驗

對選出的最佳固定流程或逐步升級策略，逐一移除各步驟，或以 2^k 因子設計（k 為步驟數）比較所有開關組合，
分析各步驟的貢獻與交互作用。例如最佳流程為「CLAHE → 去噪 → 二值化」時：

| 組別 | CLAHE | 去噪 | 二值化 |
| --- | --- | --- | --- |
| A | 否 | 否 | 否 |
| B | 是 | 否 | 否 |
| C | 否 | 是 | 否 |
| D | 否 | 否 | 是 |
| E | 是 | 是 | 否 |
| F | 是 | 否 | 是 |
| G | 否 | 是 | 是 |
| H | 是 | 是 | 是 |

### 6.7 自適應前處理（進階）

**只使用規則與統計方法**，不訓練模型（專案規則 5）。可量測的特徵：

| 特徵 | 量測方式 |
| --- | --- |
| 模糊程度 | Laplacian 變異數 |
| 亮度、過暗／過亮比例 | 灰階統計 |
| 對比 | 灰階分位數差 |
| 雜訊程度 | 平滑前後差異的統計量 |
| 傾斜角度 | 梯度方向估計 |
| 解析度 | 影像尺寸、目標區域大小 |
| 反光面積 | 高亮連通區域比例 |

規則範例：

| 量測結果 | 處理策略 |
| --- | --- |
| 亮度不足或對比低 | CLAHE |
| 椒鹽雜訊明顯 | 中值濾波 |
| 光線不均 | Adaptive Threshold |
| 傾斜角度超過門檻 | Deskew |
| 目標區域過小 | 放大 |
| 反光面積超過門檻 | 光斑修補 |

失敗重試流程：原圖辨識 → 失敗則量測品質 → 依規則選擇處理 → 再辨識 → 仍失敗則依序嘗試其他候選 → 達到最大嘗試次數後回報失敗。
候選數量與最大嘗試次數事先固定；規則門檻只依 dev 調整。

自適應策略的量測值也就是品質檢查的依據：品質檢查的門檻應設在「最佳策略的成功率開始下滑」的劣化程度，
並以「誤報」（判為品質不佳但其實讀得對）與「漏報」（判為品質良好但讀不對）評估。

## 七、辨識引擎與控制變因

### 7.1 階段零：選定辨識引擎

前處理的效果會隨引擎強弱改變很多。以 E1 合成資料的初步結果為例（尚非正式結論）：
同樣不做前處理，zxing-cpp 的成功率為 46.1%，pyzbar 為 79.7%；zxing-cpp 加上前處理為 88.3%。
若以較弱的引擎做研究，會高估前處理的效果。因此先在 dev 上比較候選引擎（皆不做前處理），選定後於所有前處理實驗中固定使用。

| 任務 | 候選引擎 |
| --- | --- |
| 商品條碼 | zxing-cpp、pyzbar |
| 電子發票 QR | zxing-cpp、OpenCV QRCodeDetector |
| 營養標示 OCR | PaddleOCR、Tesseract（chi_tra） |

以上皆為現成工具，直接使用、不再訓練。

### 7.2 必須控制的變因

| 變因 | 控制內容 |
| --- | --- |
| 原始資料 | 各組使用相同的原始樣本與變體（manifest 以 sha256 鎖定） |
| 辨識引擎 | 固定工具、版本、模型與語言包 |
| 辨識設定 | 固定參數與解碼選項；引擎內建的影像處理在所有組保持一致並記錄 |
| 影像輸入 | 固定色彩格式、尺寸處理規則與輸入方式 |
| 硬體環境 | 記錄 CPU、記憶體、作業系統與執行環境 |
| 執行方式 | 固定批次大小、計時方式；耗時取中位數 |
| Ground Truth | 使用同一份人工校對答案 |
| 實驗參數 | 每種方法的參數寫在設定檔；改參數就新增設定檔，不覆寫舊的 |
| 程式版本 | 記錄 git commit 與是否有未提交的變更 |

## 八、評估指標

### 8.1 商品條碼與電子發票 QR

每個樣本歸入下列一類：

1. **正確**：有回傳內容且與真值完全一致。
2. **誤讀**：有回傳內容但與真值不一致。
3. **未讀到**：沒有回傳內容。
4. （電子發票 QR）**部分**：只讀到一個且正確。

| 指標 | 定義 |
| --- | --- |
| 完全正確率 | 正確數 ÷ 正樣本總數 |
| 誤讀率 | 誤讀數 ÷ 正樣本總數 |
| 負樣本誤報率 | 負樣本中有回傳內容的比例 |
| 退步數 | A0 正確、但該策略不正確的樣本數 |

**策略選擇準則（正式實驗前寫定，之後不得修改）：**

1. 誤讀率不得超過 ＿＿%；
2. 符合 1 的策略中，選完全正確率最高者；
3. 完全正確率差距在 ＿＿ 個百分點以內時，選總處理時間較短者。

誤讀比未讀到更嚴重：未讀到時使用者會改用其他方式，誤讀則會帶入錯誤的產品與營養資料。

### 8.2 營養標示

| 指標 | 定義 | 角色 |
| --- | --- | --- |
| 欄位完全正確率 | 3.3 所列欄位中，數值與單位皆與真值一致的比例；另報「整張表所有欄位皆正確」的比例 | **主要指標** |
| 表格定位誤差 | 四角座標與真值的平均距離，除以表格對角線長度；另報定位成功率（誤差低於門檻） | 次要：區分定位與 OCR 問題 |
| CER | (S + D + I) ÷ N；S 替換、D 刪除、I 插入、N 真值字元數 | 次要 |

比對前的正規化規則固定且所有組相同：全形轉半形、去除空白、統一小數點與單位寫法（例如「大卡」與「kcal」）。
中文沒有天然的詞界，不使用 WER；營養標示版面固定，不使用 TEDS。

### 8.3 運算效率

分別記錄前處理時間、辨識時間與總處理時間；逐步升級另記錄嘗試次數。報告中位數與第 90 百分位數。

### 8.4 成效呈現

- 絕對提升：策略成功率減去 A0 成功率。
- 相對提升：絕對提升除以 A0 成功率。
- 各劣化條件、各劣化程度的分組結果與曲線。
- 救回數與退步數（A0 失敗但策略正確／A0 正確但策略不正確）。
- 與階段零其他引擎「不做前處理」的結果並列。

## 九、統計分析

### 9.1 分析單位

同一原始樣本的變體高度相關，不能當作獨立樣本。**信賴區間與檢定一律以原始樣本為單位**：

- **主要方法**：依 `source_id` 做集群 bootstrap（重抽原始樣本，連同其所有變體），計算成功率差異的 95% 信賴區間。
- **輔助方法**：混合效果邏輯迴歸，以前處理策略、劣化條件為固定效果，原始樣本為隨機效果，可同時檢驗交互作用（H2、H3）。
- 只看單一劣化條件、每個原始樣本只有一個變體時，可使用 McNemar 檢定（配對二元結果）。

營養標示的欄位正確率與 CER 先在原始樣本內平均，再以 Wilcoxon signed-rank test 或集群 bootstrap 做配對比較。

### 9.2 主要比較與多重比較

- **主要比較**（事先寫定）：每項任務「選定策略 vs A0」，在真實影像 test 上的完全正確率差異。
- 其餘比較（各單一方法、各組合、各劣化條件）列為探索性結果，以 Holm 法校正多重比較，報告時明確標示為探索性。

### 9.3 報告內容

除 p 值外，須報告：樣本數（原始樣本數與變體數）、各組成功率與信賴區間、效果量（成功率差異）、
救回與退步數、處理時間。統計顯著不代表實務上值得採用，須一併考慮提升幅度與運算成本。

## 十、實驗執行步驟

### 階段零：選定辨識引擎

在 dev 真實影像上比較候選引擎（不做前處理），每項任務選定一個。
**產出：** 引擎比較表與選定結果。

### 階段一：建立基準

1. 蒐集原始影像，建立 Ground Truth。
2. 依原始樣本切分 dev／test。
3. 以選定引擎計算 A0 的各項指標。

**產出：** 資料集（DVC 管理）、manifest、Baseline 數據。

### 階段二：單一方法比較

1. 產生 dev 的人工劣化變體。
2. 每個變體執行所有單一方法（不提早停止），記錄每種方法的結果與耗時。
3. 依劣化條件與程度比較各方法。

**產出：** 「變體 × 方法」結果表、單一方法比較表、劣化程度曲線。

### 階段三：組合、逐步升級與消融

1. 執行 6.4 的疊加流程。
2. 由結果表離線計算逐步升級策略，以貪婪法選出步驟與順序。
3. 對最佳候選做消融實驗。

**產出：** 最佳候選策略與各步驟貢獻分析。

### 階段四：自適應前處理

1. 定義品質量測值。
2. 在 dev 上建立規則並調整門檻。
3. 與最佳固定流程、最佳逐步升級比較。
4. 依結果設定品質檢查門檻。

**產出：** 自適應策略的效能與成本比較、品質門檻。

### 階段五：正式驗證與統整

1. 凍結所有策略、參數與門檻（記錄 commit 與設定檔）。
2. 在 test（人工劣化與真實影像）上各執行一次。
3. 依第九章分析並撰寫結論，抄入各實驗 `README.md` 的「結論」。
4. 分析失敗、誤讀與退步的案例。

**產出：** 正式結論與研究限制。

## 十一、實驗結果紀錄格式

每次執行寫成 `research/experiments/<實驗>/runs/<時間>_<label>/`（ADR 0002）：
`run.json` 記錄時間、git commit、套件版本、manifest 路徑與 sha256、完整設定；明細與彙整另存 CSV。

每個「變體 × 方法（或策略）」一列，至少包含：

| 欄位 | 說明 |
| --- | --- |
| source_id | 原始樣本代碼（統計分析的單位） |
| variant_id | 變體代碼 |
| split | dev／test |
| task_type | barcode／invoice_qr／label |
| source_type | real／synthetic |
| degradation | 劣化條件（複合情境以 `+` 連接） |
| degradation_params | 劣化參數與隨機種子（JSON） |
| experiment_id | 實驗組編號 |
| preprocessing | 前處理流程與參數 |
| engine | 辨識引擎與版本 |
| ground_truth | 真值或真值檔路徑 |
| recognition_result | 實際辨識結果 |
| outcome | correct／misread／not_found／partial |
| field_accuracy | 欄位正確率（營養標示） |
| quad_error | 表格定位誤差（營養標示） |

## 十二、預期成果與研究限制

### 12.1 預期成果

1. 三種任務的 Baseline 與引擎比較。
2. 各前處理方法在各劣化條件與程度下的效果與副作用（含誤讀）。
3. 疊加流程與逐步升級策略的比較，以及各步驟的邊際貢獻。
4. 規則式自適應策略與其運算成本，以及據此設定的品質檢查門檻。
5. 可重複執行的資料集、設定檔與評估流程。

### 12.2 研究限制

- 結論只適用於靜態照片，不外推到即時掃描。
- 人工劣化無法完全代表真實拍攝（反光、曲面、對焦失敗的型態更複雜）。
- 前處理可能改善部分影像，也可能破壞原本清晰的細節或造成誤讀。
- 結論依附於選定的辨識引擎與版本；更換引擎須重新驗證。
- 營養標示的定位與 OCR 是不同問題，須分開報告。
- 自適應規則與門檻受 dev 資料影響，泛化能力只能由 test 與新資料驗證。
- 放大只改變像素尺寸，無法還原影像中不存在的資訊。

## 十三、優先順序

先以一種任務完成整套流程，再擴充至其他任務：

1. **商品條碼**：基礎設施大部分已有（見附錄 A），真值標記成本最低，用來驗證整套方法。
2. **營養標示**：ADR 0004 指定的重心，也是主要研究貢獻；須先完成階段零的 OCR 引擎選定。
3. **電子發票 QR**：只用於冷啟動上傳與相簿匯入，優先度最低。

完整做好一種任務，比三種任務都只做少量、缺乏控制的測試，更容易得到可信且可解釋的結論。

------------------------------------------------------------------------

## 十四、研究核心總結

本研究不是找出「哪一種濾鏡最好」，而是以控制實驗回答：

- 哪些影像問題會造成辨識失敗？
- 哪些前處理方法能改善特定問題，代價（誤讀、退步、耗時）是什麼？
- 不同方法之間是互補還是互相干擾？
- 能否依影像品質量測值自動選擇處理方式？
- 前處理的改善與更換辨識引擎相比有多大？

並以可重複的流程、明確的 Ground Truth、固定的辨識引擎、以原始樣本為單位的統計分析，證明前處理的實際效果。
